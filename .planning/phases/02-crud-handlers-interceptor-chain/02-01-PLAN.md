## Phase Goal

> **Goal (verbatim from ROADMAP.md, Phase 2):** Developers get generated ConnectRPC CRUD
> handlers wired directly to the ent client, with safe partial updates and a fixed,
> privacy-aware interceptor chain — no hand-written handler code, no ent client leakage.

**MVP_MODE planner note:** the ROADMAP `**Goal:**` line for Phase 2 is *not* written in
`As a … I want to … so that …` user-story form. Per MVP-mode rules the planner does not invent
one. To get a user-story framing, run `/gsd mvp-phase 02` and re-plan. The goal above is used
verbatim as the phase's success condition.

<objective>
Prove the entire Phase 2 architecture end-to-end on one thin slice: **one entity, one RPC
(`GetOrder`), contract to wire.** A procedure constant declared in an ent schema annotation is
resolved against the committed `FileDescriptorSet` with no Go import edge to the service package,
an entc `gen.Hook` emits a gofmt-clean Connect handler into a sibling package, that handler is
wired through the fixed `authn → viewer → protovalidate → otel` chain, and a real Connect client
gets a real row back from a real ent client that application code never sees.

Purpose: this is the phase's architectural proof. Every later plan (Create/Delete, List, Update,
Manual/claims) widens a slice that already works. If procedure resolution, hook-based emission,
or the chain is wrong, that is discovered here on one commit rather than after four more layers
have landed on top of it.

Output: the `entc/` extension core, the `runtime/` framework package, a service-bearing proto
corpus with committed Connect stubs, and a self-contained fixture app under
`internal/entconnecttest/read/` whose test performs an actual HTTP round trip.
</objective>
