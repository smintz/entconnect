## Phase Goal

> **Goal (verbatim from ROADMAP.md, Phase 2):** Developers get generated ConnectRPC CRUD
> handlers wired directly to the ent client, with safe partial updates and a fixed,
> privacy-aware interceptor chain — no hand-written handler code, no ent client leakage.

**MVP_MODE planner note:** the ROADMAP `**Goal:**` line for Phase 2 is not in
`As a … I want to … so that …` user-story form; per MVP-mode rules the planner does not invent
one. Run `/gsd mvp-phase 02` if a user-story framing is wanted.

<objective>
Close the phase: the **escape hatch** and the **audit trail**, then harden the whole emitted
surface. A developer can hand-write exactly one handler via `entconnect.Manual("rpc")` and it still
runs inside the generated chain (INT-04); codegen emits a deterministic sorted claims report naming
every RPC's claimant so the escape hatch stays visible (INT-05); and every emitted file for every
verb is golden-covered and proven byte-stable across repeated runs (CRUD-06).

Purpose: INT-04 exists so the generated layer is never a wall — a developer who needs one bespoke
handler does not have to abandon the chain to get it. INT-05 exists so that hatch cannot quietly
become a back door. CRUD-06 exists so the whole generated surface is reviewable in a diff. This
plan also lands the conflict gate D-05 requires: a procedure claimed twice is a collected build
error, not a silent winner-takes-all.

**Phase boundary, deliberately not crossed:** an `unclaimed` RPC is *reported* here and must not
fail the build. Hard failure on an unclaimed RPC is DRIFT-01, Phase 5.

Output: the Manual generator and its fixture, the claims report and conflict detection, golden
coverage of every verb's emitted output, and the CI determinism job.
</objective>
