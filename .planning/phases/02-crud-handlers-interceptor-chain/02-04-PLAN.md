## Phase Goal

> **Goal (verbatim from ROADMAP.md, Phase 2):** Developers get generated ConnectRPC CRUD
> handlers wired directly to the ent client, with safe partial updates and a fixed,
> privacy-aware interceptor chain — no hand-written handler code, no ent client leakage.

**MVP_MODE planner note:** the ROADMAP `**Goal:**` line for Phase 2 is not in
`As a … I want to … so that …` user-story form; per MVP-mode rules the planner does not invent
one. Run `/gsd mvp-phase 02` if a user-story framing is wanted.

<objective>
Widen the proven slice to the **safe partial update**: a generated Update handler that requires an
explicit `google.protobuf.FieldMask` and calls `Set*` only for paths present in that mask, so a
field the caller left untouched is never zeroed.

Purpose: CRUD-04 and CRUD-05, which together resolve `entconnect.md` §9 Open Question 5 in favour
of explicit FieldMask (D-14). This is the sharpest edge in the whole project: a naive Update that
calls `Set*` for every field on a proto message silently clears every field the caller left at its
Go zero value — the exact failure `mixinforproto/README.md` has a dedicated section warning about.
The mask is checked twice: at build time against the message descriptor **and** Phase 1's
`SourceField` provenance (so a path naming an `Exclude()`d field fails the build too, D-17), and at
request time against the live message.

Output: a request-time mask validator, a build-time mask-path checker producing collected and
sorted failures, the Update generator and its template, and a fixture app whose tests cover the
empty, nested, wildcard, unknown, duplicate, order-independence, and idempotency cases plus a
negative-build fixture.
</objective>

Cover the probe-derived edges for CRUD-04 and CRUD-05 as real requests against the generated
handler. Add only new test functions; do not modify `update_test.go`.

1. **Empty / absent mask (D-16).** Three cases: `update_mask` field absent entirely, present but
   with a zero-length `paths` slice, and present with a single empty-string path. Each must return
   `connect.CodeInvalidArgument` and — asserted by reading the row back — must have mutated
   nothing. This is the destructive case: a pass here would mean every unset field was silently
   cleared.

2. **Nested and wildcard paths (D-15).** A mask path containing a dot and a mask path equal to the
   wildcard each return `CodeInvalidArgument`, and the returned message names the offending path
   verbatim so an operator can act on it without server logs.

3. **Unknown path.** A mask path naming a field that is not on the message descriptor, and a
   separate case naming the field the schema excluded, each return `CodeInvalidArgument` naming
   the path.

4. **Adjacency: duplicates and near-equal paths.** A mask listing the same path twice applies
   exactly one Set and succeeds. A mask listing a path that differs from a real one only by letter
   case is rejected as unknown — matching is exact byte equality, never case-folded.

5. **Ordering.** Two requests with the same path set supplied in opposite orders produce
   byte-identical rows; assert by reading both results back and comparing every field.

6. **Encoding.** Using the divergence Phase 1 recorded on `SourceField.LengthUnitDivergentIDs`
   (protovalidate compares Unicode code points; the derived ent field compares bytes), send a
   masked update whose value is short in code points but longer in bytes — a multi-byte string
   sitting between the two units for the fixture's own recorded bound. Assert the observed
   outcome and record it in the test's own comment as the project's answer to "whose definition of
   length applies here", referencing the recorded divergence IDs rather than restating a rule. If
   the fixture's constraint set carries no divergent ID, assert that
