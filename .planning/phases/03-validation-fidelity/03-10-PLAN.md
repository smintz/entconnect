the documentation-drift note it flags separately. None is deferred past this phase.

**WR-01 — `mixinforproto/reverse.go:217-224`.** `reverseEnum` is the one reverse-conversion
function that interpolates the actual rejected mutation value into its returned error text
(`%q` on the enum string taken from `entValue`). Every sibling failure path — `reverseScalarByKind`,
`reverseJSONMessage`, `reverseStruct`, and `reverseEnum`'s own wrong-Go-type branch — names only
the Go type with `%T` and never the payload. Today this is masked by `runtime.MapError`'s
default-case redaction, but `mixinforproto` is deliberately built and documented for standalone
adoption **with no `runtime` dependency at all** — a standalone consumer propagating the hook's
error verbatim reproduces exactly the leak this phase's own standing prohibition exists to
prevent: "MUST NOT embed the rejected field VALUE in a violation message or any error text that
crosses the RPC boundary."

**WR-02 — `mixinforproto/README.md:47-51, 213-224`.** The README still carries a "Not yet
available in this release" blockquote for `Exclude`/`Override`, and a "the fix is `Exclude`
(once available)" line, despite both being shipped, exported and load-bearing — they are the
exact mechanism 03-06's CR-03 gap closure is built around. The API reference table separately
omits `Exclude`, `Override`, `WithMessageRules`, `OnCreate` and `MessageRuleTrigger` entirely.

**Documentation drift.** `.planning/REQUIREMENTS.md`'s checklist shows VAL-09/VAL-10/VAL-11 as

verification passes record all three as `✓ SATISFIED`.

**Plus the written half of 03-09's scope boundary.** `03-VERIFICATION.md`'s first `missing:`

Output: a value-free `reverseEnum` error with its diagnosis intact and a test pinning it, a
README that matches the shipped API, and a written scope boundary for `OneofRules` in both design
surfaces.
