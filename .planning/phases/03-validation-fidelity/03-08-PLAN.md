<objective>
Close verification gap **CR-01** and warning **WR-04** from `03-VERIFICATION.md`, and
build the structural guard that makes the *next* omitted carrier a test failure rather
than a silent divergence.

**CR-01.** `checkMessageRuleReferences` walks only `msgRules.GetCel()` (`messagerules.go`
lines 96 and 116). `buf.validate.MessageRules` also carries `cel_expression` (repeated
string, field 5) and `oneof` (repeated `MessageOneofRule`, field 4) — both real and
generated in the pinned protovalidate module, neither read anywhere in the file. A message
rule declared via either alternate carrier bypasses D-10's schema-load reference gate
entirely: schema load succeeds even when the rule references an `Exclude`d or `Override`n
field, and the storage layer then evaluates that rule against a **fabricated proto3-zero
value** instead of real mutation data. That is a phantom verdict — boundary accepts and
storage rejects, or the reverse, for the same input.

**WR-04.** `WithMessageRules(trigger)` (`option.go:157-161`) discards `trigger` entirely;
the body only sets `o.messageRules = true`. Any future trigger silently behaves as
`OnCreate`.

**MVP user story** (ROADMAP Phase 3 `**Mode:** mvp`):
**As a** developer opting into `WithMessageRules(OnCreate)`, **I want to** have every way
protovalidate lets me declare a message-level rule checked by the same schema-load gate,
**so that** I cannot opt in and receive a cross-field verdict computed from data that was
never real.

Purpose: SC3's "message-level rules stay boundary-only unless opted in, and the opt-in is
safe" holds today only for the `cel` carrier. D-10 is the decision this restores in full,
D-03 is the phantom-violation class it protects, and D-24's determinism discipline governs
the failure output.

Output: carrier-complete enumeration in `checkMessageRuleReferences`, a trigger-honoring
`WithMessageRules`, new corpus fixtures for both alternate carriers, and two
declaration-surface exhaustiveness guards that fail by name when protovalidate grows a
member this package does not handle.
</objective>
