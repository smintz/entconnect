<objective>
Prove from the root module what the driverless harness structurally cannot: that ent actually
invokes the mixin hook in the real mutation path, where that hook sits relative to privacy and
schema-declared hooks, that the boundary validator is built once per process, and that the two
modules cannot silently drift onto different protovalidate/cel-go/protobuf/ent versions.

Purpose: D-13 requires two harnesses deliberately. `mixinforproto`'s driverless sweep proves the
verdicts; only a real ent client behind a real Connect handler proves the wiring. Without it, a
regression that silently stops calling the hook passes green. VAL-09 then needs the hook's
position pinned so an ent upgrade that changes ordering fails CI — asserted relatively, because
03-RESEARCH.md Pitfall 3 showed the privacy wrapper is installed only when a `Policy()` exists
anywhere on the schema, so a hard-coded index would turn an app-shaped change into a false
regression. VAL-11's gate closes the version-skew hole that would let the two layers disagree for
reasons no test could attribute.

Output: a new `internal/entconnecttest/hookwiring` fixture with policy-bearing and policy-free
schemas, a `runtime` test pinning once-per-process validator construction, a `check-dep-parity`
Makefile target over D-15's explicit five-module set, and a CI step hosting it in the existing
`GOWORK=off` standalone job.
</objective>

## Flagged assumptions (spec-less probe, unresolved)

Two of this plan's requirements returned **`unclassified`** from the edge probe — no edge
category applies cleanly, so they stay `unresolved` rather than being auto-resolved with a
backstop, and are surfaced here rather than silently dropped:

- **VAL-09 (`unclassified`)** — "ordering is documented and covered by a test that fails if ent
  changes it" has no data-shape edge. The live risk it stands in for is Pitfall 3's: a test that
  hard-codes `hooks[0]` passes today and breaks the moment an app adds or removes a `Policy()`.
  Task 1 addresses it by asserting relative order in both configurations, but the probe did not
  independently derive that criterion.
- **VAL-11 (`unclassified`)** — "CI fails when versions diverge" is a build-system property, not
  a data-shape one. The live risk: a gate that silently passes when a named module is absent from
  one `go.mod` gives false assurance, which is precisely why D-15 chose an explicit named set
  over "every shared dependency".
