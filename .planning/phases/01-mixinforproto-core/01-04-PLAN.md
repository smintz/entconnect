<objective>
Make every failure this mixin can have arrive at schema load, name itself precisely, and be
reproducible in-process. Add the `Exclude` and `Override` options, the unresolved-`oneof` gate, the
reserved-identifier collision check, collected structured errors, and the `Validate[M]` parity that
makes any of them debuggable without `go generate`.

Purpose: for a runtime mixin, schema load *is* the check phase. But `entc` runs schema loading in a
subprocess whose panic output is routinely truncated to a single line — a filed ent issue, not a
hypothesis. A failure whose first line is not self-sufficient is, in practice, a failure with no
diagnostic at all. This plan is what makes the mixin usable when the contract is wrong.

Output: a complete failure surface where every path is tested for its specific message content, not
merely for the fact that it panicked.
</objective>

## Reconciliation applied in this plan

- **R3 — the reserved-identifier catalog is narrower than CONTEXT.md implies (binds Task 2).**
  CONTEXT.md D-10 says to check derived names against "ent's known reserved identifiers (`id`,
  `type`, `label`, `edge`, `where`, `config`, `client`, and the rest of the catalog-known set)".
  RESEARCH.md fetched `entc/gen/type.go` verbatim and found the real static maps —
  `globalIdent` (26 entries) and `privateField` (16 entries) — contain **none of**
  `id`, `type`, `label`, `edge`, or `where`. Cross-checking `ent/ent#280` directly showed the
  reported `label` collision was against a **per-type generated constant** (`const Label = "..."`,
  generated fresh for every entity from its own name), producing a Go compiler
  `redeclared in this block` error — a structurally different category that no static list can
  enumerate.

  **Resolution: implement BOTH categories and be honest about the second one.**
  (1) A static catalog hand-copied from `entc/gen/type.go` — copied, never imported, because
  importing `entc/gen` would violate the module-isolation constraint that is MIX-14. This category
  panics at schema load with an `Exclude`/`Override` remedy.
  (2) A short structural supplement plus an explicitly documented Go-compiler-error fallback for
  everything it cannot cover. **No task in this plan may claim to catch all collisions at schema
  load — it cannot**, and D-10 already accepts that limitation.

  The structural supplement ships as `id` and `label` only: those are the two with direct evidence
  (every entity has an id; `Label` is confirmed by `ent/ent#280`). `type`, `edge` and `where` are
  named in D-10 but were NOT verified against ent's source, and adding them speculatively would
  reject legitimate contract field names and force adopters into an unnecessary `Override`. That
  trade is surfaced below as a flagged assumption so a reviewer can overturn it cheaply.
- **R2 (inherited, binds Task 3).** `Validate[M]` must reach the `derive` core directly and never
  `entc.LoadGraph`, which shells out through the same subprocess it exists to avoid.
