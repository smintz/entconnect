<objective>
Close VERIFICATION.md gaps 2 and 3 — both are string-translation defects in the same two files,
both hidden by the same corpus property, and both are silent data-loss at write time rather than
documented boundaries.

**Gap 2 (VAL-01 / SC4).** `delegatingFormatValidator` (`validate.go:374-388`) builds a synthetic
`dynamicpb` message carrying only the candidate field and calls `v.Validate(msg)` — a
*whole-message* validation — then treats ANY non-nil error as this field's rejection. Every other
field sits at its zero value, so an unrelated `required` poisons the verdict and the derived
validator rejects effectively 100% of inputs, valid ones included, on any realistic multi-field
message. `TestStringFormatValidators` passes only because every `StringFormat*` corpus message is
single-field **by explicit doc comment**.

**Gap 3 (VAL-03 / SC4).** `classifyRequired` tests `required && hasNotEmpty` before
`optional && required`, and the string/bytes builders always pass `hasNotEmpty=true` — so the
presence branch is unreachable for exactly the two kinds that have a `NotEmpty()`. A
presence-tracking `optional string value = 1 [(buf.validate.field).required = true]` gets
`NotEmpty()`, and ent rejects a deliberately-set empty string that protovalidate accepts. Unlike
the length-unit divergence — which was decided by the user, documented, and machine-recorded — this
one is recorded nowhere.

Purpose: this package's entire claim is verdict identity between the boundary and the storage
layer. A translated constraint that rejects valid data, or enforces a different predicate than the
contract states, is worse than an untranslated one, because it is invisible.

Output: two exact translations, three corpus fixtures carrying the shapes that break them, and doc
comments that no longer assert things the code beside them does not do.
</objective>
