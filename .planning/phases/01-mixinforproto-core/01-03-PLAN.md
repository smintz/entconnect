<objective>
Make the two-module repo operationally correct: a scripted canonical pipeline, CI that cannot go
green while the nested module is broken, a standalone-consumption proof, a documented release-tag
convention, and the presence/zero-collapse documentation that is the only mitigation Phase 1 has
for the design's sharpest edge.

Purpose: PITFALLS Pitfall 12 is a well-known Go multi-module trap set, and every one of its three
traps is silent. `go test ./...` from the repo root does not descend into `mixinforproto/`, so CI
passes green while the module is broken. A local-path override directive left in a merged PR breaks
external consumers only. A tag pushed without the `mixinforproto/` prefix cannot be fetched, and Go
module proxy caching makes a wrong tag effectively permanent. All three must be closed before any
external consumer tries to `go get` the module.

Output: a repo whose build tooling tells the truth, and docs that reach adopters before the
zero-collapse behaviour does.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → Go module proxy / GitHub Actions marketplace | CI fetches a toolchain and third-party actions and executes them with repo write-adjacent context. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Tampering | CI toolchain installation (`buf`, `actions/setup-go`) | medium | mitigate | `buf` is installed at the pinned `@v1.72.0`, never an unpinned latest reference, so a compromised or simply changed upstream release cannot silently alter generated output. | T-01-12 | Tampering | committed generated stubs and `.binpb` drifting from `.proto` sources | high | mitigate | Two sources of truth for the same contract is the exact hazard Pitfall 9 names, and a stale stub silently changes what the mixin derives while the contract reads unchanged.
