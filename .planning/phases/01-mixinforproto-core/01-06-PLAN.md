<objective>
Close VERIFICATION.md gap 1 (MIX-02 / SC1): `classify()` in `mixinforproto/fieldmap.go` never
tests `fd.IsList()`, so a `repeated string tags` falls through to `classScalar` and derives a
singular `field.String` — silently dropping the contract's cardinality. Worse, when the field
carries a format rule the derived validator closure calls `msg.Set(fd, ...)` against a
list-cardinality descriptor and panics at ent MUTATION time, not at schema load, which is the
worst possible failure timing for a design whose whole premise is "schema load IS the check
phase".

This plan adds the missing cardinality branch, routes repeated scalars/enums to a loud
schema-load failure carrying the standard Exclude/Override remedy (D-08/D-09/D-10 — never a
silent rename, never a silent approximation), preserves the existing repeated-message
skip-by-default path, and — the part that actually matters — adds the corpus fixture whose
absence made this defect invisible to five green waves.

Purpose: a contract-first tool whose entire premise is "the contract is the source of truth"
must not silently derive a scalar column for a repeated contract field.

Output: a `classify()` that is total over cardinality, a corpus that contains the shape that
breaks it, and a recorded boundary where there was a silent gap.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| protobuf contract → derivation | An attacker-or-mistake-authored `.proto` is the untrusted input to `classify`/`mapField`. It runs at build/schema-load time, never at request time. |
| derivation → ent mutation path | Anything `mapField` hands back becomes a live validator closure inside the application's write path. |
