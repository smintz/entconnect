<objective>
Prove the entire contract-to-schema path end to end on the thinnest possible slice: one
`.proto` file with one string field becomes one ent field carrying full provenance, readable
back out of a real `entc`-produced `gen.Graph`.

**User story (MVP framing):** *As a* Go developer building a contract-first ent application,
*I want to* declare one generated protobuf message type in my schema's `Mixin()` and get a
real ent field with recorded provenance, *so that* the contract — not the schema — is the
single definition of that field, and later phases can prove the two never drifted.

Purpose: this is the Walking Skeleton. Its single job is to retire the one risk no unit test
can retire — that annotations actually survive `entc`'s schema-load subprocess JSON boundary,
where Go closures provably do not. Everything else in Phase 1 expands outward from this slice.

Output: a two-module Go repo whose `mixinforproto` module derives an ent field from a proto
message and whose provenance annotations round-trip through a real schema load.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `.proto` source → schema-load-time compile | A contract file (possibly authored by a third party or an LLM) supplies pattern strings and field names that reach `regexp.MustCompile` and ent builders inside the developer's build. First-party-authored today, but not reviewed as code. |
| schema package → `entc/load` subprocess | `entc` compiles and runs the schema package via `go run` in a child process whose panic output is routinely truncated to one line. Failure signal crosses a process boundary that discards detail. |
